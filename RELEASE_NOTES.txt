Aigentron v0.1.120

For people who are not programmers: finished work no longer piles up on the disk, task titles are generated again, and active tasks come first in the list.

New
- Clearing finished work. Every task works in its own copy of the repository, and these copies are large. Now a copy is cleared when its work has been merged into the main branch (including rebase merges and merged pull requests), or three days after the task is done if its commits are saved on the remote. It is NEVER cleared while it holds uncommitted files, ignored files that are not build output (like a .env), commits that exist nowhere else (including on a detached HEAD), or while the task is running. A merged pull request only counts for the commits it contained. A message to a cleared task brings its copy back from its branch. Settings → General → "Finished work — task checkouts" lets you choose the mode (merged or done / only merged / never) and the days, shows what would be cleared and why, clears on demand, and keeps a log. It is checked every 6 hours.
- The task list shows tasks that are being worked on first (running, queued, waiting for approval, and leads whose subtasks are working), newest first within each group.

Fixed
- Task titles were not generated when the default model was unavailable (a local model not running, a revoked key) or when it was a "reasoning" model that answered with nothing. Now every available model is tried in turn, a broken one is skipped for a few minutes, and the log tells you when no model could name a task (Settings → Task titles → Try it shows the details).
- A task whose working folder had gone missing was started in that missing folder; it is now restored from its branch first.

Update note: the database gets two new columns (added automatically on start). New installations and updates have the cleanup ON with the safe rules above; set "Never" in Settings to keep every copy.
