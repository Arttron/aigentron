Aigentron v0.1.73

For people who are not programmers: agents can publish code safely, and a failed update no longer leaves the server stopped.

New
- push_branch for agents. An agent that has finished work in a project's repository can now ask to publish a branch (for example "develop" as "main" into an empty repository). You approve each push on a card; the server pushes with the project's own key, so agents still never hold any key or token. Pushes are never forced. A plain `git push` from an agent's shell cannot work by design, and the git skill now tells agents so.
- Publishing a task result into an empty repository now works (it used to be skipped because there was no main branch yet).

Safer updates (bare-metal servers)
- The updater checks free space (300 MB) before it stops the service and refuses to start when there is not enough, leaving the running version untouched.
- If anything fails after the service was stopped (for example a full disk), the previous version is brought back up automatically, including the database snapshot if migrations had run. The service file is written atomically.
- Build caches (pnpm store, npm, corepack) now live in <data dir>/cache (override with CACHE_DIR) instead of root's home directory, and are cleaned after a successful update. These protections apply from the update that installs this version onwards.

Fixed
- Checkboxes in the approval card (the "Don't ask again" options) showed up as long slider-like bars; they are normal checkboxes now.

Update note: no database changes. If a previous update stopped half-way on a full disk, free some space first (see docs/updates.md).
