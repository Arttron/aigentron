Aigentron v0.1.94

For people who are not programmers: fewer approval cards for the browser, safer previews, an alert sound, and a settings page that is no longer one endless list.

New
- Alert sound: a short sound in the dashboard when an approval (or a question) appears — a falling "uh-oh" by default, with other sounds, volume and "only when I am in another tab" to choose from (Settings → General → Alert sound; per browser). The browser plays it after you have clicked on the page once.
- Settings regrouped: General (look, titles, updates, disk), Work (approvals, run limits, repository, checks, queue, agent instructions, escalations), Security (sign-in and two-factor, signed-in devices, domains, Cloudflare, web server). MCP servers and the MCP endpoint share one tab, Voice and Vision share one.
- The browser (Playwright) no longer asks for an approval on every click, keystroke or form field while it is on the agent's own preview; on an outside site, running page scripts, uploading files and installing still ask.

Changed
- "No approvals" mode still asks about three things: a merge, anything on the main / master branch (push, checkout, reset, delete …) and anything outside the working directory. Everything else goes ahead as before; credentials, protected files and admin changes are still asked. The ordinary mode asks about the same actions too (a plain `git merge` and `git checkout main` are new there).

Fixed
- A preview could show another project's site: a dev server left behind kept its port, and the next preview took it for its own. Now a preview port must be free before the start, the process answering on it must be the one that was started, and stopping a preview ends the whole process group.
- Agents now stop the preview right after the screenshots (new `stop_preview` tool and a rule in the Playwright skill): one process, only while needed.

Update note: no database changes.
