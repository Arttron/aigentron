Aigentron v0.1.86

For people who are not programmers: moving to another server is now two commands, and the backup no longer misses your projects' folders.

New
- Moving to another server: `sudo aigentron export` on the old one (or `--to user@host:path` to send it over SSH) and `sudo aigentron import <archive>` on the new one (the same or a newer version, the same data folder). It carries the database, secrets, agents, skills, resources, attachments, every project's folder and the code (the checkouts and the agents' worktrees, without node_modules and build output; `--no-repos` leaves the code out). Add-ons and the Browser add-on's profile are not carried: re-enable the add-ons on the new server. Stop the old server afterwards (a Telegram bot and repository pushes must not run from two places). Step by step: docs/moving-servers.md.
- `aigentron backup --with-repos` adds the code to an ordinary backup. A restore refuses an archive made by a newer version (use --force to override) and warns when the data folder differs.

Fixed
- `aigentron backup` did not include the projects' own folders (`projects/<slug>`: the project's memory, library, results). They are in the archive now; backups made by older versions do not have them, so take a fresh export before moving.

Update note: no database changes.
