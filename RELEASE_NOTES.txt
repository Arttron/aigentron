Aigentron v0.1.83

For people who are not programmers: a small server no longer falls over when it runs out of memory - the one run that would have tipped it over is stopped instead of the whole service.

Fixed
- On a small machine (4 GB, no swap) the kernel killed a process when memory ran out and systemd then stopped the whole service ("oom-kill" in the log), the service restarted, the same tasks ran again and it happened again every few minutes - tasks seemed to fail even one at a time and the dashboard showed Cloudflare 520. Now: a memory guard stops the newest run before that (the task becomes "stalled", the work stays, press Continue later; AGENT_OOM_GUARD_MB, default 200, 0 = off); new runs wait for memory up to an hour; agents ask the kernel to kill them first; the service unit gets OOMPolicy=continue (applied by this update); the Node memory cap for builds is a third of the RAM; the Metrics report "system" shows memory and swap and warns when there is none; the installer reminds about a swap file. A 2 GB swap file is the most useful thing on a 4 GB machine (docs/small-servers.md).
- The low-priority wrapper for agents is tried out once and skipped when it cannot start (a temp dir that forbids running files used to make every run fail).
- A proxy error page (Cloudflare 520, 502/503/504) is shown as one plain sentence instead of pasting its HTML; the approvals selector no longer stretches the task header; room between "+ Subtask" and the list.

Update note: the update rewrites the service unit (adds OOMPolicy=continue); no database changes.
