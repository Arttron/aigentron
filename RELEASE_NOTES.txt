Aigentron v0.1.108

For people who are not programmers: an agent that writes a document no longer gets stopped for approval just because the text of the document mentions a risky word, and the settings for text filters are tidier.

Fixed
- When an agent saved a document with a command like `cat > file <<'EOF' … EOF`, words inside the document (for example "rm -rf", "git push", ".env" or "printenv" in an instruction or a checklist) were read as commands and asked for approval, sometimes with a hard block. The text of such a document is now treated as content. Anything that could really run stays checked: a delimiter without quotes, a pipe into a shell, another program reading the text, any command after the document, and the file the document is written to (credentials and protected files still ask).
- Settings → Work → Compression: each custom filter rule is a clear block with fields lined up and room around its buttons.

Update note: no database changes.
