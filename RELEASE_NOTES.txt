Aigentron v0.1.85

For people who are not programmers: a browser for the agents on any server, easier adding of MCP servers, a tidier task list with bulk actions, and a guide to working on the code directly on the server.

New
- Playwright add-on: `sudo aigentron addon enable playwright` gives the agents a headless browser (the `playwright` MCP server) on a server without Docker compose. Separate from the Browser add-on, so a personal browser stays personal. The installer was run in a Debian 12 (aarch64) container: libraries, Node, Chromium, the MCP server starts and refuses a foreign Host. It needs 0.5-1.5 GB of memory while a page is open: on a 4 GB machine keep the swap file and run one browser task at a time.
- The System navigation has "Add-ons" instead of "Browser": two tabs, Browser (the live view as before) and Playwright (status, what to type on the server). /browser redirects there.
- Adding an MCP server accepts any client's format: {"mcpServers": {...}} (Claude Desktop, Cursor, LM Studio, .mcp.json, VS Code), a single {url, headers} / {command, args} object, a "claude mcp add ..." command or a URL. The form shows what it understood; a missing type is filled in. The MCP endpoint page now gives the Claude Code command with the token header and a .mcp.json block.
- Task list: only main tasks, each with "5 subtasks - 3 done - 1 stalled" (the subtasks are on its page); a task that is idle while a subtask runs shows as running; a selection mode (Select) with Mark as done / Cancel / Delete for several tasks at once.
- Agents and providers: no delete button in the list; deleting is in the edit dialog.
- In the no-approvals mode a run that reaches the step limit or the time ceiling is continued by itself.
- docs/work-on-server.md: how to edit and test the code directly on the server (your own clone, the project's checkout, an existing clone for the default project), and why a project you work in must use worktree isolation, not shared.

Update note: no database changes.
