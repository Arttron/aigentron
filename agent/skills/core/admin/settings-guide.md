# Settings guide

Tell the user EXACTLY where to click, with the real labels below. Never invent menu items. (The rest of the dashboard: skill **dashboard-guide**.)

## Settings (`/settings`) — tabs

General, Work, Security, Providers, LiteLLM, MCP, Channels, Voice & vision, Users. (Schedules is its own page in the main menu, right after Tasks.)

**General** (everyday look and upkeep; cards top to bottom):
- *Display*: **Theme** (per browser), **Assistant** (put the mascot back), debug mode.
- *Alert sound* (per browser): a short sound when an approval card appears — a falling "uh-oh" by default; pick another (chime, ping, knock, bell), set the volume, also for agent questions, only while the tab is in the background; **⬆ Upload your own sound** (mp3/wav/ogg/m4a, up to 1 MB and 15 s, five at most; kept in that browser only — not on the server); **Test the sound**. A second block, **New messages**, plays a sound when an agent writes to the open conversation (its words and its answer, optionally only the final answer / only when the tab is in the background) — never for its steps (tool calls), also in the "all steps" view. The browser plays sounds only after one click on the page.
- *Translation* (per browser): the language the 🌐 translate button under agents' messages translates into (default: the browser's language).
- *Task titles* (see above).
- *Version & updates*: **Check now**, **Update to X** (operator confirms; restart 1–2 min; previous kept for `aigentron rollback`; Docker can't self-update: `aigentron update`). I can start it (`propose_update`).
- *Disk & cleanup*: free-space bar, what takes it, **Free up space now** (regenerable caches only). Checked every 10 min: low = banner + message to the default chat; critical = auto-clear. Attachments never auto-deleted.

**Work** (how agents work; cards top to bottom):
- *Approvals*: **No approvals mode** (admin only) = the global level; a project (its settings) and a task (🛡 selector, subtasks follow) can override it, most specific wins. Off: no cards (step/time limits go on alone), except a merge (not of the agent's own task branches `agent/…` in its worktree), an action on main/master (push, checkout, reset, delete …), anything outside the working directory (not `/tmp`, the project folder or the task's own attachments folder — `$LDS_ATTACHMENTS_DIR` is read as that path), credentials/charter files and admin changes (starting tasks for the project's agents, `propose_task`, goes on without a card).
- *Run limits*: first time window, extension while still working, quiet limit, steps per run, and at the ceiling a card asks whether a working run may go on (+N min). Env vars are defaults.
- *Questions*: the model that answers tasks started as "Just a question" (checkbox in the new-task form) or `/ask` in a chat — a light run with no working copy, checks or status report, in the reserved lane; empty = each agent's own model; a task's pinned model wins; the agent's escalation ladder still applies. Saved here (askModel).
- *Compression and filtering*: cheap model-free filters on what goes to an agent — the person's message and the answers of bulky tools (documents, knowledge bases, workspace, image/video answers). Switches for whitespace, repeated lines, quoted replies/signatures, binary blobs, long logs (head/tail kept), a length cap, the person's own regex rules, and a "Try it" box. The transcript keeps the original. Stats shows what each filter and project saved. Saved here, not in the admin's propose_settings.
- Then one form with **Save settings**: *Repository (GitHub)* (the Default project's: *Repo URL* blank = local workspace; *Base branch*; *GitHub token*; *Project subdirectory* = RELATIVE folder like `apps/web`, a URL is rejected); *Verification gate* (commands per line after each run + max auto-fix attempts); *Task queue* (concurrency), *Chat slots* (`chatConcurrency`, 0 = automatic, 2–6: chat turns and questions run in their own lane beside the task cap, wait only for free memory); *Command pipeline* (`commandPipeline` on/off, `heavySlots` 0 = automatic: heavy commands — install/build/test/tsc — of all tasks go through one queue via the `run_command` tool, only that many at once, each held while the machine is busy); *Approval timeout* (s); *Agent instructions (skill)* appended to every prompt; *Escalations* (default channel + chat/thread for questions from tasks with no channel); also `approvalChatDelay` (seconds the dashboard hears first before the chats are told; 0 = at once, -1 = never) and `approvalChatNobodyAtOnce` (send at once when nobody looks at the dashboard); **Finished work — task checkouts** (General tab, `cleanupMode` off/merged/merged_or_done + `cleanupDoneDays`): a task's own git checkout is cleared when its work is merged or N days after it is done — never with uncommitted files, with commits that exist nowhere else, or while running; a message to the task brings it back; the card previews what would go and logs what did.

**Security**: *Security* (passwords; optional two-factor sign-in with an authenticator app — each person turns it on for themselves; an operator/admin can tick *Require two-factor sign-in* for a user in Users (set up at their next sign-in) and **Reset 2FA** for a lost phone in Users; docs/authentication.md); *Signed-in devices* (own sessions, operator/admin: all; **Sign out** per device / "my other devices" / "X everywhere"); *Access* (allowed domains, empty = any; `localhost`/IPs always work unless **Only these domains**); *Cloudflare Access* (team domain + AUD, Save, **Test**; requests on real domains without Cloudflare's token are refused; localhost/IP/LAN exempt); *Web server* (port 80 optional; PEM cert + key → HTTPS on 443; `aigentron access`). I handle domains and Cloudflare via `access_status`, `propose_allowed_domains`, `propose_cloudflare_access`.

**Providers**: **+ Add provider**, **Default provider**, rows: **Test**, **Edit** (**Delete provider** is in that dialog). Codex / Claude-oauth: **Sign in**. Form: *Name*, *Kind*, *Base URL*, *Auth mode*, *Secret*, *Default model* (**Load models**), *Rate limits*.
**LiteLLM**: model routes of the gateway (advanced).
**MCP** (two cards). *MCP servers*: built-in playwright, **playwright-proxy**, github, postgres, code-intel, **research**. Add: paste whatever the server's page gives — `{"mcpServers": {…}}` (Claude Desktop / Cursor / LM Studio / `.mcp.json`), one `{url, headers}` or `{command, args}` object, a `claude mcp add …` command or a URL; the page shows what it understood (the missing `type` is filled in; the name is taken from the text), **Add**. `"readOnlyTools": ["*"]` (or names) marks tools read-only (no approvals); `"trustAnnotations": true` + **Discover tools**: server-annotated read-only tools skip approvals. Agents use a server only if in their `mcp:`. I can't change MCP servers.
*MCP endpoint*: outside clients (Claude Desktop) drive the platform. **Users**: people, roles.
**Voice & vision** (two cards). *Voice*: speech-to-text (🎤) and text-to-speech (🔊) (a provider of kind OpenAI; free local speech: `sudo aigentron addon enable voice` then *Use it for recognition and speech* — Russian + English, nothing leaves the server; **VoiceLab** — Base URL `https://api.voicelab.uz/v1`, good for Uzbek — needs a language and a voice id instead of a model, see docs/voice.md); each a switch, *Provider* (kind OpenAI: OpenAI, Groq, local Whisper/TTS by Base URL), *Model*, *Language*/*Voice*, **Test**. Telegram `/voice on|off`; dashboard 🔊 and **🎙 Voice mode**. Cloud providers receive audio/text. Mic needs HTTPS/localhost. Needs a provider key: guide the user.
*Vision*: provider + model that describe photos/video frames (not Claude/Codex sign-ins; **Test** saves first). Without it `look_at` falls back to the agent's own cloud model. `docs/media.md`.
I can change only: default agent, verification gate, concurrency, chatConcurrency, heavySlots, commandPipeline, approvalChatDelay, approvalChatNobodyAtOnce, cleanupMode, cleanupDoneDays, approval timeout, agent instructions, branch, subdirectory — never repo URL/tokens — and revert my own changes.

## Channels (Telegram)

Settings → **Channels** (**+ Add channel**): needs a bot (@BotFather) and its token (secure field, never chat). Only allow-listed chats work. In the add/edit form, once the token is entered, **Find my id → Wait for my message**: the person writes anything to the bot from their account, the form shows what they wrote and their id and asks "Add this id to the allowed chats?" (Yes adds it to the list; saved with the channel). For a channel that is already running it watches the waiting chats instead. A message from a non-allowed chat gets its id back and the dashboard shows a yellow "is this you?" line with **Allow / Dismiss**. I set it up via `propose_channel`, `request_secret`, `channels_list`. The channel setting *A plain message starts* chooses what a message with no command becomes when the chat has no active task: a **task** (default) or a light **question** (cheap model from Settings → Work → Questions); `/ask` always asks, `/new_task` always starts a task, a file always starts a task. Key requests via Telegram arrive as a one-time link (needs `PUBLIC_URL`; works once, 10 min, one value).
Quiet by default: answers and what needs the person; `/progress on|off` toggles live notes. **Quoting** a message addresses the task that wrote it; a plain one continues the active task. `/agents` lists them; `/pm text` or `@pm text` writes to one; the name alone (`/pm`) or `/agent pm` makes it the chat's agent for NEW tasks until `/agent default`. Who gets a new task from a chat: the agent named in the message → the chat's own choice → the bound project's Default agent → the channel's Default agent → the main lead; the reply says which ("→ pm"). `/done`, `/continue [text]` (dashboard: ▶ Continue), `/discuss pm architect: topic`.

## Schedules

Main menu → **Schedules** (⏰, after Tasks; it used to be a Settings tab): time ("every day at 09:30", weekdays, days, every N hours, raw cron), time zone, quiet hours, action: **post a message** (free), **start a task** (budget; updates go to that chat) or **run a script** (a shell script on the server, free, no model: runs in the project's folder with a minimal environment, time limit, last output kept on the card and posted to a chat after every run or only on failure; files a script leaves in `$LDS_OUTPUT_DIR` (a chart) are sent to the chat and deleted, `$LDS_DATA_DIR` keeps a history between runs (`docs/schedule-scripts.md`); an operator adds one here, or I propose it (`propose_schedule` kind `script`, a dashboard card with the WHOLE script; an ordinary agent and a pack cannot); a new run is skipped while the previous works). Task schedules also have **Approvals for this schedule's tasks** (follow the project / No approvals / Ask): nobody is there to answer a card at 03:00, so a job that sends a chart and deletes it should be set to *No approvals* (credentials and platform changes are still asked). Buttons: Run now, Turn on/off, Edit, Delete. Missed runs are skipped. I manage them (`propose_schedule`, `schedules_list`).

## Approvals

A risky action stops with a card: **Approve** / **Deny**; **Options**: "Don't ask again for this exact call in this task" or "…anywhere (global, expires after 30 days)" (MCP tools: same arguments only). My batches are ONE card, applied in order; my cards have no "don't ask again". Server `.env` guard rails: `AGENT_IDLE_TIMEOUT_MS` aborts a silent run; `BUDGET_TOKENS_PER_TASK`/`_PER_DAY` block a task. Approvals time out (deny) per Settings → Work → Approvals. **Where a card goes:** the dashboard first — with a dashboard tab visible it waits 10 s for an answer on the page, then goes to the chats of the task's project (or the free ones); with no tab visible, at once; a task started from a chat answers in that chat. Same rule for questions and blocked/stalled/failed notices.

## Questions from agents

`ask_user`: a card with **answer buttons** (one or several) in the dock bottom right and in Telegram (tap, text or number); first answer wins; none in 1 h → the agent chooses or reports blocked. In Telegram a task blocked on the person becomes the chat's active one: the next plain reply answers it. Blocked/stalled questions escalate to the parent lead or the default channel (Settings → Work → Escalations). `docs/questions.md`.

## Camera, video, pictures

Text files attached to my chat reach me in the prompt; other attachments I read with `read_document`. 📎 menu: **📷 Camera** (HTTPS; else the phone's camera app); videos ≤95 MB (Cloudflare) in tasks, ≤300 MB in Resources. `look_at` (photo or video frames) and `video_digest` (frames + transcript) take `every_seconds`, `at_seconds`, `pointing` / `phrases`. `show_images` shows pictures in the chat (Telegram: photo/album). `docs/media.md`.

## Discussion between agents

**💬 Discuss** (New task form, or a chat's header/⋯ menu): topic, 2–6 agents, rounds, who concludes; Telegram `/discuss pm architect: topic`. Agents answer in turn (short, read-only); the person can join; **Wrap up** → conclusion; **Stop**. *Language of the agents*: *Terse English* (default; 🌐 translate under a message) or *Your language*.

## Languages

Dashboard text is English; the person's text, names, knowledge bases, voice (50 languages) and "done"/"готово"/"完成" can be in any language. Agents talk terse English; the person gets answers in their own. `docs/languages.md`.

## Browser through a proxy

The ordinary `playwright` browser can use a proxy chosen in the dashboard: **Add-ons → Playwright → Browser proxy** (paste the seller's line `host;port;user;pass`, name it, Test, pick it or Direct; applies at once, the login is never shown). MCP server `playwright-proxy` sends ALL traffic through the operator's proxy (server-only: `PLAYWRIGHT_PROXY=res.proxy-seller.com;10000;user;pass` in `.env` — also `user:pass@host:port`, `host:port:user:pass`, `http://user:pass@host:port`; or the older `PLAYWRIGHT_PROXY_SERVER`/`_USER`/`_PASS`; then `docker compose --profile proxy up -d playwright-mcp-proxy`; add it to the agent's MCP list). `docs/browser-proxy.md`.

## Moving to another server

I cannot do it for you (it is two commands on the servers over SSH): `sudo aigentron export` on the old one, `sudo aigentron import <archive>` on the new one (same or newer version, same data folder). It carries the database, secrets, agents/skills/resources, every project's folder and the code; not the add-ons or the browser profile. Then stop the old server (Telegram bot!), re-enable add-ons, check domains. `docs/moving-servers.md`.
